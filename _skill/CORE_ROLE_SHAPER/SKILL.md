# Shaper/Designer — Skill

## Purpose
Convert an ambiguous problem into a clear one, thereby providing a clear starting point from which the subsequent implementation, verification, and operation roles can work.

## Input
- A problem or demand that is still in an ambiguous state
- The relevant work context and constraints

## Procedure (Steps)
1. Define the problem to be solved.
2. Organize the requirements.
3. Decide what to build.
4. Make clear the grounds for why it should be built.
5. Design what structure is appropriate.

## Output
Clarity — the state in which an ambiguous problem has been converted into a clear one.

## Criteria
If all three of what to build, why it should be built, and what structure is appropriate are defined it is judged PASS (clarity secured), and if even one of them is not defined it is judged FAIL (insufficient problem definition).
