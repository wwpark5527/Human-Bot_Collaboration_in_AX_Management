# 3. Authority Design — Skill

## Purpose
Set the accessing actors for each AI, data, and tool resource and document the access-authority design, thereby performing the third step of the AI Inclusive-Transformation ESG execution model (9 steps). The ESG linkage is G (Governance).

## Input
- The list of AI resources (models, agents, services), the list of data assets and the sensitivity standards, the list of tools and their scope of impact, the per-task context capital produced as the output of step 2, and the organization chart and job system

## Procedure (Steps)
1. List the AI, data, and tool resources separately.
2. Classify the sensitivity and scope of impact of the data and tools.
3. Refer to the per-task context capital and map resources, tasks, and roles.
4. Set the accessing actors for each resource (a cross-table of the resource axis × the actor axis).
5. Document it as the access-authority design.
6. Determine the procedures for granting and revoking authority and connect them to personnel transfers and job changes.

## Output
The access-authority design — the resource lists with their sensitivity classification, the resource-task-role mapping table, the details of the accessing actors set for each resource, and the procedures for granting and revoking authority.

## Criteria
It is judged PASS if the accessing actors are set for AI, data, and tools alike, the design is documented, and the granting and revoking procedures are connected; it is judged FAIL if a resource kind is omitted or it is not documented. (ESG linkage: G)
